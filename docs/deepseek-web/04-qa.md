## 3. P0 —— 两个 bug 的独立复核（真机）

脚本：`%TEMP%\awb_qa_real.py`（日志 `%TEMP%\awb_qa_real.log`）。

### 3.1 【bug②】相同问题二次提问 → 两次都要非空正文

命令：直接 `WebDriver.submit("请只回复两个字：收到")` 连续两次（`dedupe_key=None`）。

```
第1次: 2.5s | 正文 2 字 | 增量合计 2 字 | 正文='收到'
第2次: 1.6s | 正文 2 字 | 增量合计 2 字 | 正文='收到'
[PASS] 第 1 次拿到非空正文 / 第 2 次拿到非空正文（bug② 核心）
[PASS] 两次正文一致 / 第 2 次增量非空（修了"文本增量恒空"）
[PASS] 两次增量 == 各自正文（绝不丢正文）
```

**判定：✅ bug② 已修复且经真机证伪"仍会返回空正文"。** 机制复核：`_wait_answer` 用
"文本 ≠ 基线 **或** `answerCount` 增加"两条信号取或（`web_driver.py:653`），并在返回前
用 `emitted` 做收尾对账补齐正文（`:660-666`）——与真机行为一致。**注意**：走到服务层时，
完全相同请求会被幂等表镜像（`local_server.py:260`）而**不重发**，两条防线都成立。

### 3.2 【bug①】答复提取的抗污染

- 真机两次取回正文均为 `'收到'`，**不等于**任何页面 UI 文案 ✅
- 页面确实存在干扰控件：`ds-toggle-button` 文案「智能搜索 / 深度思考 / 联网搜索」
  （`%TEMP%\awb_qa_pageinspect.py` 读出）。`answerText()` 优先精确类名
  `.ds-assistant-message-main-content`，结构兜底显式排除 `button/[role=button]/toggle`
  与 `UI_NOISE` 文案（`web_driver.py:228-264`）。
- 另一独立证据：R2 第 1 轮正文 = 纯 `<tool_call>…write_file…</tool_call>`，**未混入 UI 文案**。

**判定：✅ bug① 已修复且经真机证伪"仍会误抓 UI 文案"。**

## 6. 非阻塞发现（建议修，但不阻碍 v9.14.0 验收）

### 6.1【低危】`no_key` 白名单不足以保证"Key 被清空仍可用"

- 现象：`LLMClient` 对 `no_key` provider 只跳过"缺少 API Key"判空（`llm_client.py:155`），
  但若 Key 为**空串**，仍会发出 `Authorization: Bearer `（空），本机服务
  `_auth_ok()`（`local_server.py:297-300`）要求非空 → 返回 **HTTP 401** → 调用失败。
- 与设计不符：`02-arch.md 1.4 #1` 明确声明"即使 key 被清空也照常工作"——**该声明不成立**。
- **可达性：实际不可达。** 实测（`%TEMP%\awb_qa_keyflow.py`）：全新工作区、
  设置页 load→save 往返、落盘再载入，`api_keys['deepseek_web']` **始终 =**
  `'sk-local-deepseek-web'`（占位 key 被输入框预填并原样写回）。**只有用户手动清空
  Key 输入框**才会触发。
- 硬约束 1 的**最低要求（提供占位 key）已满足**，故非验收阻塞。
- 建议（择一）：① 服务端对回环请求接受空 Bearer；或 ② `_stream_once` 在
  `provider.get("no_key") and not key` 时回落到 `"sk-local-deepseek-web"`。

### 6.2【中低危·体验】网页自身报错时不会快速失败，而是空等满 `answer_timeout`

- 现象（§4.1，真机证据）：网页显示 DeepSeek 自身横幅「服务器暂时不可用 / 已停止」后，
  `answerText()` 仍是上一条旧答复、`answerCount` 未增 → `_wait_answer` 的
  `fresh=False` 恒成立 → 一路轮询到 `WEB_ANSWER_TIMEOUT=300s` 才报 TIMEOUT。
- 影响：用户最长会**静默等待 5 分钟**才看到失败提示（提示本身是中文、且**不会重发**，符合红线）。
- 建议：`_wait_answer` 在"提交已 ack、但答复数/文本长时间（如 5~10s）无任何变化、
  且页面出现错误类文案（`服务器暂时不可用`/`已停止`）"时**提前判失败**，给出明确中文原因。
- 另：`WEB_ANSWER_TIMEOUT=300s`、`WEB_ACK_TIMEOUT=12s`、幂等宽限 `90s` 仍为**建议值**
  （工程师 03-impl §4.6 亦标注未标定），本次实测一次 `run_python` 耗时 **61.6s**，
  说明"深度思考/长回答"下单轮可能远超短回复，需按实测重新标定。
