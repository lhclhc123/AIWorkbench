# PRD：把 DeepSeek 网页版接入 AIWorkbench

- **项目名**：`deepseek_web_provider`
- **语言**：简体中文
- **目标版本**：v9.13.1 → v9.14.0
- **原始需求**：用户看到开源项目 DSH-webtokens，希望"把它装进我的程序里"——让 AIWorkbench 能把已登录的 DeepSeek 网页版当成一个模型来用（免 API Key）。
- **背景约束**：AIWorkbench 是本地 PyQt6 单用户桌面应用（非 Web、非多用户），已有完整 Agent 循环 + 51 工具 + 9 页面。本次**不是从零做产品**，而是给现有产品**增加一个模型来源**。用户唯一判断标准：**有没有产物**（能不能真写文件、真跑代码）。

---

## 1. 产品目标

**一句话定位**：让 AIWorkbench 用户凭一个已登录的 DeepSeek 网页标签页，就能选到"免费且够强"的 DeepSeek，像用普通模型一样对话和调工具。

**成功标准（可衡量）**
1. 模型菜单里出现"DeepSeek 网页版"，选中后**多轮对话可用**，且**无需装 Node / 浏览器扩展 / 中转站**。
2. 选中它开启 Agent 模式时，能**真的调用至少 3 个工具并产生真实产物**（如真写一个文件、真跑一次代码并拿到输出）。
3. 打包为 exe 后，在**另一台只装了 Chrome 的机器**上，用户完成"登录一次网页"即可使用；全程有可读的状态提示（未安装/未启动/未登录/已连接/等待出字）。

---

## 2. 用户故事

### 场景一：首次接入
1. 作为用户，我打开"设置 → 模型"能看到一个 **DeepSeek 网页版** 区块，点一次按钮就把网页拉起来，**以便**我不用去命令行折腾就能开始。
   - 验收：按钮点击后本机 Chrome 打开 chat.deepseek.com；界面出现"已启动网页"状态。
2. 作为用户，如果我还**没登录**，界面明确告诉我"去网页里登录一次，登录后回来点自检"，**以便**我知道下一步该干什么而不是卡着没反应。
   - 验收：未登录态显示登录引导文案 + 一个"打开网页"按钮；登录完成后点"连通性自检"能变成"已连接"。

### 场景二：日常使用
3. 作为用户，我在模型下拉框选"DeepSeek 网页版"，直接开始聊天，**以便**用上比现有免费模型更强的能力。
   - 验收：选中后发一条消息能拿到回复；再来一条能记得上文（多轮）。
4. 作为用户，我开启 Agent 模式让它"帮我写个程序",它**真的把文件写进磁盘并真的跑起来**，**以便**确认它和别的模型一样能干活。
   - 验收：产出真实文件路径 + 真实运行输出；不是只在聊天里贴代码。
5. 作为用户，我随时能看到**连接状态**（网页是否连上、是否登录、当前是否"等网页出字中"），**以便**长等待时知道它没死。
   - 验收：状态行在"等待网页输出"时可见；等待超过阈值有明确说明而非静默卡住。

### 场景三：出问题排查
6. 作为用户，当**登录失效**时，我看到一条能看懂的中文提示和"去登录"入口，**以便**自己几步就能修好。
   - 验收：提示非报错堆栈、含可操作按钮；重新登录后恢复正常。
7. 作为用户，当**DeepSeek 网页改版**导致能力失效时，我收到"网页结构可能已变、暂不可用"的可理解说明，**以便**我不误以为是自己的问题。
   - 验收：失败信息区分"未登录 / 网页改版 / 超时 / 其他"，并给出下一步建议。
8. 作为用户，当我**没装 Chrome** 或**页面卡住不动**时，界面告诉我缺什么或可点"重试/重启网页"，**以便**我能自助恢复。
   - 验收：无 Chrome 时给出明确缺失提示；卡住时提供重试入口且**绝不重复发送**同一条提问。

## 3. 需求池

### P0（必须有）
- **模型菜单出现新选项**：模型下拉中出现"DeepSeek 网页版"一项，可被选中并生效。完成 = 选中后请求确实走网页通道（不是静默回退到其它模型）。
- **多轮对话**：同一会话连续多轮，模型能引用上文。完成 = 连续 3 轮内容相关且不串台。
- **真实工具调用**：Agent 模式下真写文件、真跑代码。完成 = 至少一次"写文件 → 运行 → 有真实输出"的完整闭环，产物落盘且非空。
- **登录引导与状态**：一键拉起网页 + 未登录时给引导。完成 = 未登录/已登录两态可见且可操作。
- **连接状态提示**：显示 未安装/未启动/未登录/已连接/等待出字。完成 = 状态随实际变化实时更新。
- **失败时的可理解报错**：把底层失败翻译成中文人话并给下一步。完成 = 四类失败各有对应文案，无英文堆栈裸露。
- **打包可分发给别人用**：exe 在只装 Chrome 的干净机器可用。完成 = 新机器登录一次后跑通对话 + 工具调用。

### P1（重要）
- **连通性自检按钮**：一键检测"网页可达 + 已登录 + 能取回一条答复"。完成 = 输出明确通过/失败项。
- **等待网页出字的可见性**：等待期间显示进度提示，超时有说明。完成 = 长回复时用户能看到"仍在等待"。
- **重试/重启网页入口**：卡住或异常后可一键重连。完成 = 重试后不需重启整个应用。

### P2（可选）
- **首选/默认模型设置**：允许把 DeepSeek 网页版设为默认。完成 = 设置项可保存并在新会话生效。
- **客户端侧串行保护**：并发请求时排队而非混乱。完成 = 同时发两条不会串话。
- **上下文超长时的处理提示**：长对话给出"网页会话过长"提醒。完成 = 触发时提示可见。

## 4. UI 设计稿（"设置 → 模型"中的 DeepSeek 网页版 区块）

### 布局（文字 + ASCII 草图）

```
┌─ 设置 · 模型 ───────────────────────────────────────────────┐
│  模型选择:  [ DeepSeek 网页版            ▾ ]                  │
│                                                             │
│  ── DeepSeek 网页版 ──────────────────────────────────────  │
│                                                             │
│   状态:  ● 已连接        （四种态之一，见下表）              │
│                                                             │
│   [ 启动/打开网页 ]   [ 连通性自检 ]   [ 重试 ]              │
│                                                             │
│   提示: 首次使用请在弹出的网页里登录一次 DeepSeek，          │
│         登录后回来点"连通性自检"。（灰色小字）               │
│                                                             │
│   ⓘ 本功能通过自动化驱动本机 Chrome 页面工作，非官方 API。    │
│     网页若改版可能失效，账号存在被判定异常使用的潜在风险。   │
└─────────────────────────────────────────────────────────────┘
```

### 四种状态（状态行使用既有 v9.13 风格：一行灰胶囊 + 状态圆点）

| 状态 | 圆点 | 状态文字 | 可用按钮 | 用户该做什么 |
|---|---|---|---|---|
| 未安装 | 灰 | 未检测到 Chrome | 打开安装说明 | 去装 Chrome |
| 未启动 | 灰 | 网页未启动 | 启动/打开网页 | 点一下启动 |
| 未登录 | 黄 | 网页已打开，未登录 | 打开网页 · 连通性自检 | 在网页里登录一次 |
| 已连接 | 绿 | 已连接，可以对话 | 连通性自检 · 重试 | 直接去聊天 |

### 交互规则
- **一键启动**：点"启动/打开网页"→ 拉起本机 Chrome 打开 chat.deepseek.com，用户首次登录一次（登录态持久化，之后免登）。
- **连通性自检**：点按钮后依次报告三项——① 网页是否可达 ② 是否已登录 ③ 能否取回一条答复；逐项显示 ✓ / ✗ 与中文说明。
- **出错时给用户看什么**（对齐既有风格：助手消息无框直排、工具调用/中间过程=一行灰胶囊、结论文块左侧强调竖线）：
  - 未登录 → 黄色状态 + "请先在网页里登录 DeepSeek" + [打开网页]。
  - 网页改版 → 红色提示胶囊 + "网页结构可能已变，该功能暂不可用，已记录问题"。
  - 等待超时 → 灰色进度胶囊 + "已等待 N 秒仍未返回，可点重试"（**不重发**同一条提问）。
  - 无 Chrome → 灰态 + "未检测到 Chrome，请先安装"。
- **等待出字**：等待期间在对话区显示一行灰色胶囊"正在等待 DeepSeek 网页输出…"，出结果后替换为内容。
- **风险知情**：设置页固定一句灰字风险说明（自动化驱动网页、改版可能失效、账号潜在风险），满足用户"风险要讲清楚"的偏好，但**不做弹窗反复追问**。

## 5. 待确认问题（影响产品形态）

1. **是否把 DeepSeek 网页版设为默认模型**？（影响新会话默认行为与"自动模式"是否包含它）
2. **是否允许并发**？网页会话单 worker 串行，是否需要在客户端做排队 + 明确告知"正在忙"？
3. **上下文超长时**：自动"新建对话 + 携带摘要"（体验好但可能丢细节）还是**直接提示用户**？
4. **失败时是否允许自动回退**到其它免费模型？（现有策略是 `strict` 不回退；网页版是否沿用？）
5. **是否在"自动模式"里把网页版纳入候选**，还是仅在用户显式选择时才用？

---

## 6. 明确不做什么（防范围蔓延）

- 不做多账号 / 账号切换。
- 不做云端中转、不搭服务器转发。
- 不做浏览器扩展、不装 Node 常驻依赖。
- 不依赖第三方中转站或代理服务。
- 不修改 Agent 循环、工具协议、现有页面结构。
- 不追求原生 API 参数（temperature / top_p / max_tokens / 原生工具 schema）——网页版没有。
- 不做语音/视觉走网页版（仅文本对话与工具调用）。
- 不做移动端 / Web 端适配（本产品是单机桌面应用）。
